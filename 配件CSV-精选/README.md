## 采样规则

1. **兼容性覆盖优先**：先按插槽、接口、类型、规格、容量档位等关键维度分组，每组保底抽取若干条（插槽类每组 3–5 条，接口类每组 3–4 条，其余维度按重要度 1–20 条），确保「每种插槽都有 CPU/主板/散热器可用、每种接口都有显卡/硬盘可用」。
2. **剩余名额按新→旧补齐**：年份最新优先 → 价格从高到低 → 产品名，直到达到 150 条（机箱因板型/侧板维度多，自然扩到 165 条，仍在上限 200 内）。
3. 年份脏数据（库里有 2 条写成 20117 / 20225 的）按「无年份」处理，排到最后，不会抢占头部。

## 数据缺口（原库本身没有，不是抽样漏掉）

以下 5 个「主板板载 CPU」插槽在全库 2,365 条散热器里没有任何一条声明支持，所以散热器表无法覆盖：

`G34`、`Integrated AMD`、`Integrated Atom`、`Integrated Pentium`、`Integrated Xeon D`

这 5 类属于服务器/板载方案，实际散热由主板原装散热片解决，装机时不单独选散热器。

## 字段与编码约定

- UTF-8 带 BOM、CRLF、RFC4180 转义，Excel 双击不乱码、数据库导入可用。
- 每类只保留本类**有值**的列（全空列已删），列集稳定不随抽样变化。
- `价格人民币元`/`价格美元` 为纯数字列（BuildCores 最低价快照）。
- 布尔列（`无风扇` `ECC支持` `RAID支持` `NVMe`）只有 `是`，空即不支持。
- 空单元格 = 原库该字段为 NULL。

## 跨表配单顺序建议

1. `cpu.插槽` → 选 `motherboard.插槽` 相同的板（还要看 `motherboard.内存` 的 DDR 代数）。
2. `cooler.插槽` 用逗号多值列表，需包含 CPU 插槽才可用。
3. `gpu.长度` ≤ `pc_case.最大显卡长度`；`cooler.高度` ≤ `pc_case.最大散热器高度`。
4. `ram.类型` + `ram.规格` 与主板匹配；`storage.接口` 与主板 M.2/SATA 通道匹配。
5. `cpu.TDP + gpu.TDP` 的 1.3–1.5 倍 ≤ `psu.功率`，机箱再核 `psu.长度` 与 `pc_case.扩展槽`/`硬盘位`。
